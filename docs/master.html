Master Node Orchestration:
From Math to Grid in 5 Minutes

The Master Node coordinates real-time NATS work queues, automates container baking and WASM cross-compilation, dispatches redundant tasks, and enforces majority consensus.

1. Prerequisites 2. Infrastructure 3. Stream Contract 4. Auto-Baking 5. Launch Master 6. Anti-Cheating ⚡ Interactive Generator
Step 1

Prerequisites & Environment

The Speedboat Master runs as an unprivileged binary orchestrating a high-throughput pipeline. Before launching, ensure your host has:

Go Toolchain 🐹
Go 1.22+

Required to compile and run cmd/master.

Docker Engine 🐳
Docker 24.0+

Used for backing services and optional OCI image baking.

Message Fabric ⚡
NATS JetStream

Handles pub/sub work queues & WASM Object Store distribution.

Step 2

Deploying the Infrastructure

Speedboat uses NATS with JetStream enabled to distribute work packages and stream compiled WebAssembly binaries. We provide an out-of-the-box Compose file:

examples/docker-compose.yaml 
services:
  nats:
    image: nats:2.10-alpine
    container_name: speedboat-nats
    restart: unless-stopped
    command:
      - "-c"
      - "/etc/nats/nats.conf"
    ports:
      - "4222:4222"                # Native TCP client port (CLI & agent.exe)
      - "8222:8222"                # HTTP monitoring dashboard
      - "8080:8080"                # WebSocket port for browser nats.ws workers
    volumes:
      - nats_data:/data
      - ./nats.conf:/etc/nats/nats.conf:ro

  registry:
    image: registry:2
    container_name: speedboat-registry
    restart: unless-stopped
    ports:
      - "5000:5000"                # Local Docker registry for Heavy Mode OCI containers
    environment:
      REGISTRY_STORAGE_DELETE_ENABLED: "true"

volumes:
  nats_data:
  registry_data:

Start the backing cluster with one shell command:

bash 
docker compose -f examples/docker-compose.yaml up -d
Step 3

The Standard Stream Contract (Math-to-Grid)

Scientists never need to master distributed concurrency or network protocols. Speedboat defines a clean Unix-pipeline contract:

Phase A: Splitter

generator.py

Emits a JSON array of task specifications to stdout. The Master slices these into NATS work items.

Phase B: Worker

logic.cpp / logic.wasm

Reads one task JSON from stdin, crunches the simulation, and prints the result JSON to stdout.

Phase C: Aggregator

reducer.py

Reads consensus-verified result batches from stdin and writes the final aggregated research dataset.

examples/prime-cnt/generator.py 
import json
import sys

# Slices search space [10,000,000 -> 100,000,000] into 1,000 sub-tasks
tasks = []
step = 100000
for idx, start in enumerate(range(10000000, 20000000, step)):
    tasks.append({
        "task_id": idx,
        "start": start,
        "end": start + step
    })

# Write JSON stream to stdout
print(json.dumps(tasks))
sys.stdout.flush()
Step 4

Baking Scientific Payloads

Speedboat provides automated baking routines for both lightweight WebAssembly and native OCI containers:

Target: Lite Mode & Browser WASI WebAssembly

Compiles your C++/Rust/C source file directly into an optimized .wasm bytecode file using ephemeral wasi-sdk: 

go run ./cmd/master build-wasm -p ./examples/prime-cnt
  • Tiny artifact size: 1 MB – 15 MB
  • Zero external dependency runtime via wazero
  • 85–90% native speed via in-memory JIT
Target: Heavy Compute OCI / Docker Image

Bakes and tags an unprivileged container image and pushes it to the local registry for GPU passthrough: 

go run ./cmd/master build -p ./examples/prime-cnt
  • Full hardware acceleration (CUDA, ROCm, AVX-512)
  • Ideal for legacy Fortran & dynamic C++ libraries
  • 100% native CPU and GPU performance
Step 5

Launching the Master Grid

Run the master orchestrator to load tasks, publish work streams to NATS, and host the live browser dashboard:

bash 
go run ./cmd/master run \
  --project-dir ./examples/prime-cnt \
  --nats-url nats://localhost:4222 \
  --registry localhost:5000 \
  --web-port 3000 \
  --wasm ./examples/prime-cnt/logic.wasm

Orchestrator CLI Flags Reference

--project-dir, -p Path to project folder containing project.yaml (default: .)
--nats-url NATS server endpoint (default: nats://localhost:4222)
--wasm Path to compiled .wasm file to serve to browser volunteers
--web-port HTTP port to host the live volunteer web dashboard (default: 3000)
Step 6

Consensus Verification & Anti-Cheating

Volunteer nodes are unauthenticated and untrusted. The Speedboat Master enforces strict mathematical consensus before feeding results into the research dataset:

⚖️

Redundancy Dispatch

Every task payload is assigned to 3 separate volunteer nodes across different IP addresses to prevent collusion.

🎯

Epsilon Consensus

2 out of 3 results must agree. Floating-point variations across x86-64, ARM, and WASM software floats are verified within defined epsilon bounds (1e-7).

🚨

Spot-Checking Trap Tasks

The Master periodically dispatches deterministic verification tasks with pre-computed outputs to detect and ban bad actors.
